## Checked behavior and ownership

**E28 predicate.** bank_preparation.cpp try_begin_direct checks actual cached runtime before fresh resource iteration. Fresh iteration skips every non-kind1 command, uses actual resource lookup and admits alternate flag bit0 without inventing a normal cache. Normal readiness locks the real weak cache and moves strong NormalCache owners into direct_samples, preserving exact sample identity even when the donor PreparedProgram retires. That vector survives through construction and is cleared by lower retire. Source LB kind comparison and40-byte source command step are consistent with typed parsed command iteration. Unsupported alternate construction remains named failure later; this change does not implement it.

**Existing runtime reference.** The same bank mutex protects record.cached lookup and references increment; both wrapper allocations precede active=true and increment. No fresh resource lease is acquired for this branch. build checks bank revocation; take_result checks again; finish_build does not increment cached references twice. RuntimeProgramReference::Impl release decrements once and frees last deferred cached preparation outside bank/own locks. Local retained/cached variables precede bank_lock, so failure unwinding releases the bank lock before destroying retained resources. Native Session uses the actual PreparedBank, not a separate simulated pointer or Service token.

**Direct failure and real retry.** NativePlayWork::build separates runtime readiness from the later consumer. retry_direct_construction_on_worker admits only runtime_built, direct_attempted, fresh, not-ready, not-cancelled, no-ordinary-callback work. It retires the actual old RuntimeProgramWork before admitting a replacement on the same bank/selector, retains the same public association/reservation, preserves direct_constructor_failure, then clears worker identity/body state. A new resource worker claims that queued replacement. Consumer/copy/priority/clock failure occurs in complete and never enters this constructor-retry branch. Lower retirement before worker transfer respects thread-owned leases. Failure admitting the replacement destroys the unpublished work and releases real association/private resources; no successful stub is returned.

**Canonical revocation/publication.** commit_play_plan rechecks actual native Session load_state before publication, after incumbent retirement, and after unlocked clock sampling. This resolves canonical close/unload even if a retained preparation/reference still exists. Runtime submit initially checks failure/closed under publication then lifecycle; direct completion uses the same publication check as run_resources. A failed-output admission passes false to complete, producing closed rather than activating. Construction retirement occurs before the actual consumer, so lower leases do not cross into callback publication. The public accepted handle may still have a failure completion, matching the queued API's separation of admission and activation.

**Main reservation/reentry.** submit_game_sound reserves game_sound_references before invoking automatic Runtime ingress, then pushes an already allocated value. The RAII Main guard is set before callbacks and cleared after all returns/unwinding. The owner helper rejects recursive record operations before they can erase/reallocate the reservation. Runtime's analogous guard rejects recursive submit/resume and shutdown before waiting or reacquiring publication. It is released by RAII outside the inner lock scopes. These guards address actual newly synchronous construction/consumer reentry; arbitrary external mutation/destruction of public Main fields is outside their contract.

**Lock/disposal paths.** Lower selection takes NativePlayWork mutex -> RuntimeProgramWork mutex -> bank. It performs no resource-domain acquisition under bank. Construction acquires domain with registry/job locks released. Retry drops NativePlayWork mutex while retiring/admitting lower work. Completion drops job mutex before preparation/owner operations. Runtime selects queued jobs under lifecycle -> job -> lower -> bank; it drops lifecycle before construction or completion. Publication -> lifecycle is used only for admission checks, with lifecycle dropped before calling complete; output fail also uses publication -> lifecycle. Owner cleanup callbacks can reenter guarded Main/Runtime functions and receive operation_active instead of waiting. No new owner -> lifecycle edge while owner lock remains held was found in the inspected paths. Polling destroys only already-retired work; its plan/reference/admission have already been released. Resource-domain final backing disposal is serialized outside its mutex. Existing safety behavior for worker-internal impossible states (terminate) was not newly relaxed.
