## One concrete finding: domain ownership can escape [P2]

Target runtime/include/mka/retail_camera_world.hpp exposes NativeRetailRenderCameras' constructor publicly and leaves copy/move implicit while the object retains raw borrowed session_. The public API permits an independently owned value via `auto escaped=*session->render_cameras(f);` (or direct construction). After releasing the last Session,the separately owned escaped domain can still invoke its methods,which dereference session_ through session_access. This is the avoidable constructor/copy ownership escape,not a claim that ordinary borrowed pointers should survive their owner.

The target NativeRetailGameSession is already noncopyable;that does not prevent copying its publicly copyable member type. Private frozen-header static assertions prove both public copy and move construction are available. COPYABILITY_FROZEN.json pins compiler/header and successful syntax-only result.
