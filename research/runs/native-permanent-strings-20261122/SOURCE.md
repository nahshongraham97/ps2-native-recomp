## Verified data-only image

All actual images have header words0/1 zero (no function records and no
external-reference tail), one variable record, name `string_list`, and78 string
elements. The8-byte type region is `8300000001043200`:216D80 reads one field at
type+4 and primitive4 at type+5. Other bits/bytes are retained without guessed
field meanings. The type region is not executable bytecode.

2170E0 lays out eight LE32 header words, function pointer slots/records,
variable pointer slots/records, names, string bytes, type bytes, variable cells
and external tail. A variable record has five LE32 words followed by its
reference list. Its name/type offsets and string references are one-based.
216D80 uses a nonzero string reference as a record-list index and adds the
selected relative offset to the string pool; zero remains a null value.
The variable's cell-start/element count establish the exported array alias.

Native decoding resolves these **file-data** references once into immutable
native text ranges/value leases. It never creates a guest address map or
executes an interpreter. Unknown functions, imported variables, external tail
or non-string shapes remain named implementation failures. Native range
checks use checked widened arithmetic; malformed overflowing/wrapping offsets
are refused, not converted into host pointers.
