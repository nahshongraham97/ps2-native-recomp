# Native sound-file error propagation

Source review found two regressions in the preexisting opened-content adoption work. The NativeFile read branches in the new file adapters return FileRead.error without copying it into ArchiveFailure/PayloadFailure. Archive cursor restoration also passes the original failure object to NativeFile::seek, whose verified implementation clears its error argument on entry. Successful restoration can therefore erase the original read error. The prior NativeFile caller explicitly carried FileRead.error into its fail result and used a separate restoration error.

A focused native linker-injection fixture now exercises actual SoundArchiveBacking and SamplePayload calls. It verifies that the injected native read error reached both the read and restore operations before checking preservation. Header and payload errors, cursor restoration and a distinct restoration failure are included. It does not substitute any game service or create physical audio/video endpoints. Reproduction on the uncorrected source is pending; production correction has not yet been applied. The caller's Main/catalog integration and native-only game acceptance remain OPEN.

The first fixture build failed before execution because the seek hook assumed a libstdc++ error_code mangling while the actual compiler uses libc++. The source was not corrected yet. The fixture now wraps only NativeFile::read, authenticates that injection, observes actual successful cursor restoration, and closes the real file in the restoration-failure case so the actual NativeFile::seek returns bad_file_descriptor. The failed link and warnings remain in reproduction-01/build.json. No check was weakened.

Reproduction02 compiled and failed on the exact expected assertion after proving read injection and actual cursor restoration. The production correction now copies NativeFile FileRead.error into each adapter failure and uses an independent ArchiveFailure for cursor restoration. A successful restore preserves the original read failure. A failed restore replaces it with cursor_restore_failed and the real restoration error. Corrected verification is pending.

Verification01 passes the corrected error fixture plus the opened-content archive and queue clients. The error fixture is now extended to actual adopted NativeContentFile archive/sample reads as well, requiring read_failed, the original host error and the preserved native cursor for both header and payload failure. This covers both supported native file representations. Production source is unchanged by this extension.
