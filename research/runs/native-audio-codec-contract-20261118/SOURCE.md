# Native audio codec boundary, 2026-11-18

Initial source-analysis phase: read-only original MSL/LIBSD IRX, generated MSL source and pinned MS2 inspection; that phase made no build/game/model/settings changes. Later implementation and standalone verification are recorded below. This identifies a concrete original transfer/pitch boundary, not complete codec or playback acceptance.

## First proved boundary: encoded bytes reach LIBSD unchanged

Normal loader0x2DE10 reads20-byte custom header (0x2DF34, generated line99298). Header+0 is never loaded by this function. Header+4 is signed-divided by4 at0x2DF58..0x2DF68 (99463..99528) to choose transfer chunk sizing; it is not a demonstrated codec selector. Header+8 supplies signed16 object count; header+0x0C supplies descriptor+0x20 rate; header+0x10 supplies per-plane byte count. Existing source record separately establishes the count2 block rearrangement; no plane-major interpretation is made here.

For count1, read0x28724 copies the raw source payload to a transfer buffer (0x2E0E8). Queue function0x34BF4 receives source pointer, sample-memory destination and byte length; stores these unchanged into job+0x0C/+0x10/+0x14 at0x34C3C/40/44 (generated212214/223/232). Worker0x3496C..0x34988 (209305..209414) forwards job+0x14 as fifth argument, source+0x0C as a2, destination+0x10 as a3, and mode as a1 to imported LIBSD ordinal17 at0x283B0. Original MSL import table at IRXfile0x2FC names libsd v1.05 (name0x308), ordinal17 stub file0x340/ordinal instruction0x344. No PCM software decode or additional VAG container parsing occurs on this mono path.

Original libsd.irx export table at file0xB0 names libsd v1.05 and ordinal17 points to object0x1890 (.text object0,file0xB0). That export accepts the same transfer arguments and manages device transfer state; no decoder coefficient contract was established from it. Hardware/sample-memory transfer is an original implementation boundary, not an accepted native ownership model. A host codec must consume owned serialized bytes directly; retaining a2MiB window,24voice array, register interface or guest pointers would not follow the native architecture direction.

Descriptor+0x48 initially0x1000 at0x2E82C..834 is the neutral fixed pitch factor; actual event/service multipliers are applied by0x2C0CC before this routine. Thus header rate participates directly in pitch conversion; it is not a sample index. Device reference48000 should be represented as a retail pitch-ratio contract, not a forced native output device rate.

Initialization0x343F0 sets original parameter entry0x0300 to0x000F and0x0400 to0x1FC6 at0x34424/34 (203721/203787), for both original cores. ## Actual bytes versus existing data decoder

First normal extent is absolute MS2file0x22188,20-byte header; raw encoded payload starts0x2219C. First block is16zero bytes. Second block is `05 00 00 00 00 00 00 00 00 00 00 00 ac c5 0f 21`. Earlier informal preview stating the entire second block was zero after05 was corrected to root; this record pins actual bytes.

Existing runtime/src/iop/audio_service.cpp:183..219 provides a reference PS-style ADPCM block decoder:16bytes→28samples, low nibble first, shift from firstbyte low4bits, predictor high4bits, coefficients(0,0),(60,0),(115,-52),(98,-55),(122,-60), bias32 then shift6, signed16 saturation and two-sample history. Secondbyte flag masks0x01/0x02/0x04 govern end/repeat/loop-start in that implementation. This is existing compatibility code, not proof that original MSL contains these coefficients or host-owned scheduling. Its g_ram mask, voice state, device cycles/registers/envelope machinery must not be imported into a native data-only codec.

Bounded first344 directory records yield7950 unique normal count1 extents after deduplication by absolute offset/length. Every payload size is16aligned; all5,821,182 blocks have firstbyte predictor<=4, shift<=12, secondbyte onlybits0..2. Final flags are7 for7796extents and3 for154. This strongly corroborates PS-style ADPCM compatibility and contradicts treating bytes as generic PCM or a VAG file with a standard header. It is data compatibility evidence, not an independent codec coefficient/rounding/flag oracle. No arbitrary waveform/sample-name association or heard-output claim is made.

## Safe native seam and limits

A narrow host codec boundary can take owned raw count1 payload bytes, explicit decoder history, and emit PCM plus observed block flags/positions, without sample RAM, guest addresses, device cores or voice limits. The exact coefficient/rounding/flag behavior currently has only the existing reference implementation plus compatible raw data, not independently verified original hardware output. Count2 transform, alternate streams, flag-driven playback looping and envelope timing remain separate unresolved contracts. Preserve raw header/unknown metadata and do not infer authored defaults or skip unsupported encodings.

## Approved native codec implementation batch

Read-only playable backup runtime/src/iop/spu2.cpp164..191 matches current audio_service.cpp byte arithmetic: same five coefficient pairs, signed16 nibble expansion, arithmetic shifts, bias32, clamp before s1/s2 update. Only the current helper adds saturation logging. Backup was not modified. New data-only codec files implement this canonical predictor<=4/shift<=12 subset with portable floor division; unsupported encodings fail explicitly. Bulk decode stages all PCM, opaque block flags and history privately; an invalid suffix publishes none. No loop/device/voice/window state is imported. Hand-derived first two predictor samples for history100/50 and zero nibbles: filter1=94/88, filter2=139/169, filter3=110/83, filter4=144/181.
